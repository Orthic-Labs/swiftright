## Other facts checked

- CLI surface (`right-release --help`): build = `release|build|package`, publish = `publish|upload|publish-update|github`, signing = `sign-windows|sign-updater|create-mac-updater|signing-agent`, `dmg build`, `publish swift` (library publication, not app packaging: `publish-swift.mjs:1-8,65-66`). No `msix`, `appx`, `swift build`, or `app` subcommand.
- `doctor`: `cli/right-release.mjs` maps `doctor` to `release.mjs --doctor`; it requires a config file and was not run (instruction: help only).
- Swift in the package is limited to: ownership scanning of `Package.swift` (`ownership.mjs:195,347,413`) and library publishing (`publish-swift.mjs`). Not app packaging.

## Missing adapters / prerequisites owned by @rightkit/release

1. **Toolchain preflight by project type**: gate `cargo`/`rustc` (`build-release.mjs:332`) and `src-tauri` target-bridge (`preflight.mjs:187-205`, `build-release.mjs:438-440`) on the presence of a Cargo manifest; add a SwiftPM preflight (`swift`, `--version`) keyed on `Package.swift`.
2. **MSIX signing contract**: add `windows-msix-signed-v1` beside `release.mjs:50-51`, extend the gate at `release.mjs:131-140`, and sign the `.msix` through `sign-windows.mjs` (already generic). Must verify Publisher subject matches the manifest (not present today).
3. **MSIX pack adapter**: invoke `makeappx.exe pack` from the already-probed SDK path (`preflight.mjs:228`), with manifest validation, and register the artifact role in `sealRelease` (`build-release.mjs:444-456`).
4. **App Installer / MSIX update route**: generate `.appinstaller` XML and add an update route through `publish-update.mjs`. Choose whether MSIX signature trust suffices or a separate updater signature is required (decision, not source).
5. **Configurable updater signer**: replace hardcoded `pnpm exec tauri signer sign` (`sign-updater.mjs:37-50`) with a per-config signer command or a non-Tauri scheme.
6. **Windows runtime-DLL staging adapter**: enumerate the Swift runtime DLL set from the built executable (not present in source), copy into the staged payload before raw signing, and require each listed DLL in `sign.prePackageFiles` with Authenticode verify (`sign-windows.mjs:42,61`). Exact DLL list is unverified until a real Swift Windows build exists.
7. **macOS nested-code signing**: add recursive discovery or completeness validation for Mach-O/frameworks inside `.app` before `sign-macos.mjs:34-41` runs, with inside-out ordering (inference from current explicit-list behavior).
8. **Make `makeappx` check conditional** (`preflight.mjs:225-236`): currently required for every Windows preflight, including NSIS/portable apps (verified by the `if (windows)` guard).
