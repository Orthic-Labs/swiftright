## Missing Swift / C ABI adapters per owner (SwiftRight needs)

No owner exports a C ABI today, so every Rust owner below needs a C shim (cbindgen or manual `#[no_mangle]` surface) before Swift or GPUI-side C callers can use it. Items are inferred from source and the owner table above.

1. `rightkit-settings` (settings-persistence): C ABI and Swift adapter. Swift has no equivalent.
2. `rightkit-db` (sqlite-storage): C ABI for open, migrate, backup, and recovery. Swift has no SQLite adapter. Resolve version drift (0.3.1 local vs 0.3.0 registry) first.
3. `rightkit-secrets` (os-credential-store): Rust C ABI for Windows Credential Manager (`src/windows.rs`). Swift already has `RightKitAppleCredentials` and `KeychainLicenseStore`, but these are Apple-only and scope-limited (synced/device). A cross-platform namespace contract (Swift and Rust) is needed.
4. `rightkit-process` (owned-processes): C ABI for kill-on-close job handles and process trees. No Swift adapter.
5. `rightkit-framed-sidecar` (framed-sidecar): C ABI or Swift port of the JSON-lines reader and writer with limits.
6. `rightkit-service` (local-services): C ABI or Swift client for `service.json` discovery and the current-user socket. Resolve drift (0.1.1 local vs 0.1.0 registry).
7. `rightkit-shell` (desktop-shell, clipboard, notifications): Tauri-free split required. Extract `clipboard.rs` and `notify.rs` (and `window_state.rs`, `autostart.rs` if needed) into a crate without the unconditional `tauri` dependency, then add a C ABI. No file-dialog adapter exists.
8. `rightkit-hotkeys` (global-hotkeys): publish first, then C ABI over CGEventTap and WH_KEYBOARD_LL primitives. Swift adapter absent.
9. `rightkit-logs` and `RightKitDiagnostics` (structured-logging): confirm JSONL schema parity across Rust and Swift, then C ABI on the Rust side. Swift already has `JSONLDiagnosticStore`.
10. `rightkit-crash` (crash-reporting): C ABI for native capture and report hand-off, plus a Swift crash adapter (none exists).
11. `rightkit-qa` (desktop-qa): GPUI or AccessKit driver. Needs a non-Tauri backend.
12. `rightkit-automation` (desktop-automation): publish from staged-unverified, then C ABI over the UIA (Win) and AX (Mac) engines. Swift adapter absent.
13. `@rightkit/release` and `@rightkit/updates`: Tauri-free update-policy rewrite, or invoke the release CLI as a process. No Swift adapter.
