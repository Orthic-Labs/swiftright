# Queue, CLI, host operations & storage v0.1

Queue opens a ticket only when semantic dependencies are parity or share its declared bootstrap group. One active claim owns a block until `expiresAt`; renewal creates receipt. Competing claim becomes `conflict`, never overwrite. Expired claims return to open after recorded expiry. Tickets close only with bound gate receipt. Only maintainer-signed waiver may bypass requirement; waiver is scoped, evidenced, expires, & does not turn a block into parity.

CLI commands accept artifact hashes, are idempotent by canonical input hash, & cache only successful immutable outputs. Exit `0` pass/cache-hit, `1` assertion failure, `2` invalid input/schema/hash, `3` blocked prerequisite/host, `4` partial resumable run, `5` internal fault. Partial work writes receipt with completed outputs & deterministic resume token derived from case hash, tuple hash, operation & completed-run hashes. Resume verifies all inputs/tuple unchanged; mismatch starts fresh & preserves prior partial receipt.

Mac host provisioning pins VM image, login session, display geometry, scale, colour profile, locale/fonts, capture & AX/input permissions; preflight records host hash. Windows host uses one desktop lane: acquire owner lock before every windowed run; retain lock through cleanup; after crash, record process/window state, reclaim only stale lock under host policy, reset host, & preflight again. Native-only interactive runs use qualified isolated session when available; until then, shared Dell desktop is allowed only while holding `D:\Claude\desktop.lock`, with foreground checks before every action & abort-on-focus-loss. Never delete Dell files over SSH. Failed preflight or recovery is blocked.

Store artifacts content-addressed, immutable, checksum-verified, & retrievable by hash. Retain receipts, captures, raw timing, native trees, candidates, accepted goldens, review records, faults & host metadata for reproducibility. Community access is read-only to published artifacts; acceptance lanes & promotion writes require maintainer authority. Retention deletion needs separate host policy & deletion receipt; none is implied by this protocol.
