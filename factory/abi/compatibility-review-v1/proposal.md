# ABI 0.7 compatibility recommendation

Proposal-only source review; no renderer/header/bridge/doc changes, compiler, native or remote execution.

Human requirement is unchanged ABI0.6 host loads & runs against DLL implementing ABI0.7. Existing proposal's exact-minor refusal cannot satisfy it. Current Swift loader resolves legacy bootstrap, passes88 bytes, validates minor6/table136/count16, then resolves legacy get_api & passes136 bytes. Merely appending structs or changing minor causes deterministic startup rejection.

Keep legacy contract frozen; add explicitly named revision exports/types. Suggested names: `swr_bootstrap_query_v07`, `swr_get_api_v07`, `swr_bootstrap_info_v07`, `swr_api_v07`. DLL supports two views, not one globally bumped table. Legacy `SWR_ABI_MAJOR=0`, `SWR_ABI_MINOR=6`, `SWR_API_FN_COUNT=16`, `BootstrapInfo`, `Api`, C mirrors & Swift legacy loader stay unchanged. New constants separately name0/7/22. All existing exports, enum/status values, layouts/offsets, callbacks, ownership, layout/measurement, ready/event ordering & run behavior remain unchanged.

Sizes above are bytes, not function counts. Preserve legacy actual Rust minimum-size acceptance, including oversized buffers; do not reinterpret header's `min(caller_size,sizeof)` comment as permission to change legacy behavior. Short calls must leave all caller bytes unchanged. Versioned paths use same simple full-size minimum contract. Caller pointer must address correctly aligned valid writable storage of declared size; ABI cannot validate arbitrary pointer memory. Both discovery functions & table retrieval remain allocation/thread/callback-free, panic-contained & thread-safe. Build complete local value after argument validation, then write one exact typed value; avoid growing legacy Rust types or writing108/184 through88/136 pointers.

`v07` types may embed legacy prefix for layout proof or repeat fields with static offset assertions. Bootstrap prefix offsets remain identical but minor/API size/count intentionally differ. API pointer offsets0–15 remain8–128; new offsets136–176. Entire136-byte prefix cannot be byte-identical because new table `struct_size` is184 rather than136; compare pointer addresses/signatures & each offset, not header bytes. No reserved slot reuse. Existing standalone108/184 layout mock is useful layout evidence after adapting names, never compatibility execution proof.

New Swift0.7 loader resolves versioned bootstrap first, validates full0.7 identity/sizes/arch/pointer width before resolving versioned get_api, then checks table size/reserved/non-null pointers. Missing versioned exports on legacy0.6 DLL yields typed unsupported/startup error before callback/function use. No silent downcast or fallback promising0.7 functions. Existing0.6 loader must resolve existing names & accept new DLL's unchanged0.6 view without recompilation. Bootstrap query must not select global runtime mode: querying must remain side-effect-free & multiple discovery callers must not alter later legacy behavior.

Settled-ready guarantee currently in0.7 proposal is behavioral change separate from appended evidence exports. Do not apply it to legacy `swr_run` or same16 legacy pointers. This negotiation proposal does not choose opt-in run behavior; if needed, design separately versioned run/options contract before implementation. Appended capture exports observe existing rendering without changing legacy callbacks/layout/scheduling; capture-off legacy path must preserve prior behavior/cost.
