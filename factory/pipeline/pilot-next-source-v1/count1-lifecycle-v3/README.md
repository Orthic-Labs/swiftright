# Count1 lifecycle-v3

Prospective Rectangle Count1 coordinator derived from the reviewed `coordinator-count1-r1.ps1` source. It preserves child capture's 30-second renderer-window deadline, 15-second native-exit cleanup, UIA/renderer release proofs, retained parent handle, & lock CAS ownership.

Outer budgets are explicit: setup/lock/scheduler registration 180 seconds, capture/result observation 60 seconds, & cleanup/final receipt/release 60 seconds within one 300-second envelope. Scheduler disable is bounded separately; final `task-result.json` is read during cleanup even when capture reports failure. Parent kernel terminal proof remains mandatory before lock release, so capture failure cannot be promoted to success or release without owned evidence.

Interactive task atomically publishes `task-start.json` after self-job admission, then records `desktop-availability.json` from its own thread desktop & `OpenInputDesktop(DESKTOP_READOBJECTS)` before dispatch/host launch. It requires readable `Default` input desktop, performs no activation/unlock/prompt, & fails closed when desktop is unavailable while still publishing final task result. Capture records bounded `EnumWindows` rows (PID, HWND, visibility, title, class, client size) after launch & once at window deadline, with .NET `MainWindowHandle` & bounded wait evidence, separating process-handle evidence from owned-window inventory. Each snapshot is retained under phase-specific `owned-window-inventory-<phase>.json` output, so deadline evidence cannot overwrite post-start evidence. Kernel exit proof stores raw unsigned & checked signed exit values.

This packet is source-only. Root stages exact dependencies & executes controls/native effects.

`recipe-binding-control-v1.ps1` is an optional preflight control. It requires `plan.recipeRef` & `sourceInputs.recipeRef` to match exact path, hash, & byte count, then verifies repository-contained recipe bytes before native launch. Missing, changed, reserialized, escaped, or symlinked recipe refs reject.
