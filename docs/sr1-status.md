## 20 October: R4b scaled text delivered (#42)
- **Implementation:** a one-line Text under `.scaleEffect` is shaped at its point size × the factor and placed at its scaled origin. The size is floored to half points within the 9–40 pt table, and text styles use their macOS size. The baseline lands at factor × the unscaled baseline.
- **Evidence:** CI run 39420788106 at 3105dfaf4 passed scale-text-v1 20/20. That case is digits-v1's four rows at ×1.5. Its text regions, exclusions and position tolerances are scaled about the anchor, and its accessibility bounds tolerance is 0.25 pt, because UIA reports whole pixels while macOS frames fall on half pixels.
- **Fallback:** wrapped text, custom fonts and sizes outside the table keep their measured size, centred, and are counted.
- **Known difference:** at 33 pt the Windows font switches to its Display optical size.

## 21 October: text and bitmaps under a curved clip (#43)
- **Change:** a text run or bitmap under a non-rectangular `clipShape` is drawn once per band of the clip's inside. Rows with the same inside spans are merged, and each span is a renderer rect clip. This is exact clipping with a one-pixel staircase where SwiftUI anti-aliases, and needs no ABI change (ABI 0.12 is still deferred).
- **Evidence:** CI run 39463019762 passed clip-bitmap-v1 20/20. Bitmaps are drawn on both sides, outside the edge band is exact, and in the band the maximum difference is 106 with 8% over 32. Host tests: 3 cases (crossing, inside, outside).
- **Review:** Oracle PASS-WITH-CAVEATS.
- **Caveats:**
  - Glyph ink outside the node's bounds (italic overhang) is cut when banded, or unmasked when wholly inside.
  - Each commit scans the region (about 64k lookups for a 2× notch cell), and a crossing run draws about once per pixel row. Optional hardening: an early exit and a cache per mask and region.

## 21 October: layout under scaleEffect matches SwiftUI to the sub-pixel (#44)
- **Rule:** SwiftUI lays out a `.scaleEffect` subtree in the scaled view's own coordinates (origin 0), snaps it there, then places it at the scaled view's snapped origin and scales it. The runtime records each node's local snapped frame (`scaleLocalFrame`) with a local placement pass, and the host draws scaled content from those frames. The anchor is the centre of the exact frame.
- **How it was found:**
  - CI-Mac probes showed that unscaled snapping already matched (probes `half-pixel-centre-v1`, `stack-ties-v1`).
  - Under ×1.4, the seven-row `stack-ties-scaled-v1` matched only the local rule. Snapping absolute positions was a pixel off on two rows.
- **Evidence at the final code:**
  - R4, run 39467077724: 6/6 cases including both half-pixel cases.
  - `stack-ties-scaled-v1`, run 39469177999: 20/20, all 14 row edges within 0.02 px of the Mac.
  - `scale-text-v1`, run 39470683102: 20/20.
  - R6, run 39469210989: 4/4 including `clip-bitmap-v1`.
- **Tests:** runtime 602/602, host 341/341.

- **Decision:** Astra chose option A: revert, keep the patch and evidence, and close. TSF reproduced the same failure while adding about 800 lines and untested input-lifecycle risk (other IMEs, R10). Logged in the workspace `decisions.md`.
- **Lessons for any TSF revival (in the patch):**
