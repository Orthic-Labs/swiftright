# Hub base gap check by compile probe

Date: 14 October 2026. Requested by RightKit session "Rk3" for RightKitHub (shell, section registry, settings kit, components, charts drawn with shapes). Compile evidence only: a probe that compiles says the API exists in the Windows runtime, not that it draws or behaves as on the Mac.

## Method

- One Swift file per candidate, one SwiftPM module per file, so one failure never hides another: `probes/hub-base-gap/Sources/<id>/Probe.swift` (generated by `probes/hub-base-gap/make_probes.py`; 33 probes). Each file starts with the SwiftRight case-host pattern `#if os(Windows) import SwiftRightRuntime #else import SwiftUI #endif` and the same body compiles in both.
- **Windows:** `probes/hub-base-gap/run.ps1` on the Dell, headless `swift build --target <probe>` (toolchain `6.4.0+Asserts`, language mode 5) against the staged runtime `09e184945-cc18ed0f` (`probes/sr0-s/fresh-runtime`). Output in `D:\Claude\swiftright\.work\hubgap-run2-20261014\` (`results.txt`, one log per probe). No GUI, nothing in the Sandbox.
- **Mac control:** `probes/hub-base-gap/run-mac.sh`, `xcrun swiftc -typecheck -target arm64-apple-macos14.0` against the real SwiftUI SDK, module cache on the internal disk. **All 33 probes type-check on the Mac**, so every Windows failure is the runtime lacking the API, not a bad probe.
- Only the first error per probe is quoted. After a missing type the compiler may not report later gaps in the same file, so a probe that names one missing symbol can hide a second; probes are split where that mattered (P05, P05b, P05c, P09, P09b, P10, P10b, P10c).
- "Gated" means a delivered SR1 block exercises the API in its case witnesses (`docs/proven-controls.json`, `factory/pipeline/**/Witness.swift`). "Works" is only claimed for those. Windows pixel, behaviour and metric caveats of those blocks are in `docs/sr1-status.md`.
- Textfield blocks 13-15 are in-progress (not delivered); none of the rows below depends on them.

## Reading it for the hub base

- Charts and rings are blocked on `Path`, `StrokeStyle`, `LinearGradient`, `Circle.trim`, `rotationEffect`. What exists and is proven: `Rectangle`, `RoundedRectangle`, `Circle` with `.fill` and `.stroke(_:lineWidth:)` and `.frame` sizing. A bar chart or a sparkline built from many sized `Rectangle`s needs none of the missing APIs; a line chart, area chart, arc or ring cannot be drawn with the delivered controls today (an observation from the probes, not a measured design).
- Confirm dialogs: use `.confirmationDialog` or `.alert` (block 17). `.sheet` is missing.
- Navigation shell: `NavigationSplitView`, `NavigationStack`, `.toolbar`, `.searchable`, `Form`/`Section`/`Picker`/`Slider`/`Grid`, `ProgressView` do not exist. A sidebar list with selection exists (`List(selection:) { ForEach }`, gated). Menu, Divider, Spacer, LazyVStack, `.task`, `@Observable` compile but nothing proves their Windows behaviour.
- `List` initialisers that take a data collection do not exist; build rows with `ForEach` inside the content closure.
